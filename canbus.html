CAN Bus Fleet Tracker

A Bluetooth odometer logger for heavy trucks, built with a Raspberry Pi Pico 2 W

Overview

Fleets need mileage for fuel tax reports, maintenance schedules and billing. Most of the time someone walks out and writes the odometer down by hand. This project is a small device that plugs into a truck's diagnostic port, reads the odometer from the truck's J1939 network, and sends it over Bluetooth to a laptop. A Python script then saves each reading to an Excel file.

It is based on PiCCANTE, an open-source CAN bus tool for the Raspberry Pi Pico. I kept the hardware idea and wrote a much simpler program that only does one job.

Status: prototype. The decoding logic has been checked with sample J1939 messages. It has not been installed on a vehicle.

How J1939 Works

Inside a truck, the engine, transmission, brakes and dash all talk on a network called the CAN bus. It is two wires, CAN-High and CAN-Low, twisted together. Heavy trucks use a set of rules on top of CAN called J1939. Every message has a number called a PGN (Parameter Group Number) that says what is inside it.

PGNNameWhat's inside
65248Vehicle DistanceTotal distance, 0.125 km per step
65217High Resolution Vehicle DistanceTotal distance, 5 meters per step

Trucks broadcast these messages on their own, over and over. The logger does not have to ask for anything. It just listens.

Three things to know:

  1. Grounds must connect. The truck, the transceiver and the Pico all share ground.
  2. Remove the 120 Ω resistor on the transceiver board (usually marked "121"). The truck's network already has its own.
  3. Power from USB for testing. Pin B has battery power, but it needs a buck converter to step it down first. Never put 12 V straight on the Pico.

Code

The Pico program is written in C++ with the Arduino IDE. It does three things.

1. Listen at 250k

Almost every heavy truck runs J1939 at 250,000 bits per second.

can = new ACAN2040(0, CAN_TX_PIN, CAN_RX_PIN, 250000, F_CPU, canCallback);

2. Pick out the distance message

Every time a message comes in, the code pulls the PGN out of the message ID. If it is 65248, the odometer is in the last four bytes. J1939 sends numbers lowest byte first, so the code puts them back together and multiplies by 0.125 to get kilometers.

unsigned long pgn = (id >> 8) & 0xFFFF;

if (pgn == 65248) {
  unsigned long raw = msg->data[4] + (msg->data[5] * 256UL)
                    + (msg->data[6] * 65536UL) + (msg->data[7] * 16777216UL);
  odometerKm = raw * 0.125;
}

A value of FFFFFFFF means "not available," so the code skips it. Some trucks only send PGN 65217, so the code checks for that one too.

3. Send it over Bluetooth

Once a minute, the Pico sends one line of text with the truck name and the odometer in kilometers:

ODO,TRUCK_01,123456.0

Instructions

1. Set up the Arduino IDE

  1. Add the board URL in File → Preferences:
    https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json
  2. In Boards Manager, install Raspberry Pi Pico/RP2040/RP2350.
  3. In Library Manager, install ACAN2040.
  4. Select Tools → Board → Raspberry Pi Pico 2 W.
  5. Select Tools → IP/Bluetooth Stack → IPv4 + Bluetooth.

2. Upload the logger

Open OdoLogger_J1939.ino, change truckName and bluetoothName for the truck, and upload.

3. Set up the laptop

pip install pyserial openpyxl

Pair with OdoLogger_TRUCK_01 in Bluetooth settings. Then set PORT at the top of odometer_to_excel.py:

  • Mac: /dev/cu.OdoLogger_TRUCK_01
  • Windows: the "Outgoing" COM port in Device Manager → Ports

4. Run it

python odometer_to_excel.py

To try it without a truck, set TEST_MODE = True in the script. It will make up readings.

The script writes fleet_odometer_log.xlsx with two sheets:

Takeaways

  • Listening is easier than asking. J1939 trucks broadcast most of their data, so a reader does not have to send anything.
  • Units matter. The raw number means nothing until you know the scale: 0.125 km per step for one PGN, 5 meters for the other.
  • Hardware basics come first. A missing ground or an extra termination resistor will stop it from working no matter how good the code is.
