Transit Schedule Adherence Analyzer

August 2026

This tool compares when a bus was scheduled to leave each timepoint with when it actually left. It works with any agency that publishes GTFS and GTFS-Realtime data. This data can be valuable for assessing whether changes need to be made to a schedule or transit operations.

I tested it on Butler County Regional Transit Authority in Ohio.

Download the code (zip)

Instructions

1. Get the GTFS schedule

Most agencies post their GTFS on their website, usually on a "Developers" or "Open data" page. You can also find it on Mobility Database or Transitland. Make sure the schedule covers the dates you want to look at.

2. Get GTFS-Realtime vehicle positions

You need the Vehicle Positions feed. Agencies usually don't keep old realtime data, so you will probably need to collect it yourself. Find the feed URL on the agency's developer page (some need a free API key), then run this in Terminal to save it every 20 seconds:

mkdir -p realtime
while true; do
  curl -s -o "realtime/vp_$(date -u +%Y-%m-%dT%H-%M-%SZ).pb" \
    "https://example-agency.com/gtfs-rt/vehiclepositions"
  sleep 20
done

Leave it running for as many hours or days as you want. Press Control + C to stop.

You can also use a public archive like gtfsrt.io, or ask the agency if it has a private log of vehicle position history.

3. Install

Unzip the download, open Terminal in that folder, and run:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e .

4. Run

python -m tdp.history --start [YYYY-MM-DD] --end [YYYY-MM-DD] \
    --gtfs path/to/gtfs.zip --rt path/to/realtime/

5. Open the results

Results are saved in the output folder. Open report.html in a browser, or leave_times.csv in a spreadsheet.

On time means between 1 minute early and 5 minutes late.

  • Schedules that need changing: the Blue Line left early 25% of the time, so its schedule has more time than it needs.
  • Stops that need more time: Miami Station D, the Meijer/West Hamilton Park & Ride and Market Street Station on the R3, and Baltimore St at 14th Ave, First Ave at Clinton St and Yankee Rd at Meadow Ave on the Gold Line were usually about 5 minutes late.
  • Most reliable: the Oxford routes and the Green Line.
  • Most in need of improvement: CincyLink and CincyLink Express. Morning trips were 24 to 41 minutes late.
  • Hardest times of day: around 8 AM, noon and 4 PM. Could leave times be altered?
  • Equipment problems: the Red Line had no GPS data after about 1:30 PM.

This is one day of data. More data would show which of these happen every day so that specific routes or leave times may be adjusted. The .csv files could be used for further analysis in another project for analyzing longterm route performance.
